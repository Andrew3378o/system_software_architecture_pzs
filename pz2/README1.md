## Завдання 2.1
 - Напишіть програму для визначення моменту, коли time_t
закінчиться. 
- Дослідіть, які зміни відбуваються в залежності від 32- та
64-бітної архітектури. 
- Дослідіть сегменти виконуваного файлу.
## Технічна реалізація
Дане завдання є класичною задачою для порівняння однієї з відмінностей між 32-розрядними та 64-розрядними системами. Ця відмінність - розмір типу даних, який використовується для зберігання значення часу, яке минуло з початку епохи Unix. 32-розрядні систем використовують 4 байти, 64-розрядні - 8, через що колись для 32-бітних систем існувала, так звана, проблема 2038 року, оскільки саме приблизно до того часу 4 байти для зберігання часу у секундах переповнюються.Системи сприймуть це як 13 грудня 1901 року, що може призвести до збоїв у базах даних, сертифікатах безпеки та логіці роботи програм. Сучасні 64-бітні системи вирішують цю проблему розширенням типу до 8 байтів. Для експериментальної перевірки цього явища при компіляції програми необхідно використати прапорці ```-m32``` чи ```-m64```, які вкажуть компілятору під яку систему необхідно виконати цей процес.
## Використання 
Щоб вказати компілятору про компіляції під 32-бітну систему необхідно ввести команду: 
```
gcc -m32 task2-1.c -o task2-1
``` 
Для відповідної програми на 64-бітній системі необхідно ввести команду: 
```
gcc -m64 task2-1.c -o task2-1
```
Після успішної компіляції програму можна запустити за командою
```
./task2-1
```
Для дослідження розмірів сегментів виконуваного файлу необхідно скористатись наступною командою:
```
size task2-1
```
## Приклади використання
При виконанні програми під 32-бітну систему можна побачити вивід схожий на це: 
```
Розмір time_t на цій архітектурі: 4 байт(ів)
Максимальне значення time_t: 2147483647 секунд після Епохи Unix
Цей час відповідає даті (UTC): Tue Jan 19 03:14:07 2038
```
При виконанні програми під 64-бітну систему можна побачити вивід схожий на це:
```
Розмір time_t на цій архітектурі: 8 байт(ів)
Максимальне значення time_t: 9223372036854775807 секунд після Епохи Unix
Значення занадто велике для стандартної функції gmtime()!
```
При дослідженні сегментів виконуваного файлу 32-бітної програми можна побачити вивід схожий на це:
```
   text    data     bss     dec     hex filename
   2074     320       4    2398     95e task2-1
```
При дослідженні сегментів виконуваного файлу 64-бітної програми можна побачити вивід схожий на це:
```
   text    data     bss     dec     hex filename
   2283     632       8    2923     b6b task2-1
```
## Аналіз результатів
З порівняння сегментів виконуваних файлів можна зробити наступні висновки:
1. Сегмент text (код програми): У 64-бітній версії він більший (2283 байти проти 2074). Це зумовлено тим, що машинні інструкції архітектури x86-64 та адреси пам'яті (вказівники) займають більше місця (8 байтів замість 4).
2. Сегмент data (ініціалізовані дані): Також збільшився у 64-бітній версії (632 байти проти 320). Основна причина полягає у збільшенні розміру вказівників, а також у зміні правил вирівнювання пам'яті (memory alignment), які використовує компілятор та стандартна бібліотека C.
3. Сегмент bss (неініціалізовані дані): Розмір змінився мінімально (з 4 до 8 байтів), оскільки в самій програмі не використовується велика кількість глобальних неініціалізованих змінних, а різниця викликана вирівнюванням під капотом бібліотеки часу.
4. Загальний розмір (dec): Як наслідок, 64-бітний бінарний файл є загалом більшим і потребує більше оперативної пам'яті при завантаженні.
