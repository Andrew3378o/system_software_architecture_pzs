## Завдання 2.3
Скомпілюйте й запустіть тестову програму, щоб визначити приблизне
розташування стека у вашій системі:
```c
#include <stdio.h>

int main() {
    int i;
    printf("The stack top is near %p\n", &i);
    return 0;
}
```

Знайдіть розташування сегментів даних і тексту, а також купи всередині
сегмента даних, оголосіть змінні, які будуть поміщені в ці сегменти, і
виведіть їхні адреси.
Збільшіть розмір стека, викликавши функцію й оголосивши кілька
великих локальних масивів. Яка зараз адреса вершини стека?
## Технічна реалізація
Для виконання завдання базовий код було розширено. Щоб дослідити віртуальний адресний простір процесу, програма ```task2-3.c``` оголошує змінні різних класів пам'яті та виводить їхні адреси за допомогою специфікатора ```%p```:
- Сегмент Text (Код): Отримано адресу самої функції ```main```.
- Сегмент Data: Оголошено глобальну ініціалізовану змінну ```data_var```.
- Сегмент BSS: Оголошено глобальну неініціалізовану змінну ```bss_var```.
- Купа (Heap): Динамічно виділено пам'ять за допомогою функції ```malloc()```.
- Стек (Stack): Виведено адресу локальної змінної ```stack_var```. Для перевірки напрямку зростання стека викликається додаткова функція grow_stack(), всередині якої створюється великий локальний масив (на 10000 елементів типу ```int```, що займає 40 КБ пам'яті), після чого виводиться його адреса.

Після запуску відповідних команд можна побачити наступний вивід:
```
Сегмент Text (код функції main):   0x5cb26a7e4215
Сегмент Data (data_var):           0x5cb26a7e7010
Сегмент BSS  (bss_var):            0x5cb26a7e7018
Купа / Heap  (heap_var):           0x5cb28195f2a0
Початкова вершина стека:           0x7ffc01d6c36c
Нова вершина стека (в grow_stack): 0x7ffc01d62700
```
## Аналіз результатів
З отриманих шістнадцяткових адрес можна зробити чіткі висновки про класичний розподіл віртуальної пам'яті процесу в операційній системі (архітектура x86-64):
- Розташування статичних сегментів (Text, Data, BSS): ці сегменти розташовані у найнижчій частині адресного простору (адреси починаються з `0x5cb2...`). Простежується чіткий порядок: найменшу адресу має сегмент коду (`0x5cb26a7e4215`), одразу за ним розташовані глобальні ініціалізовані дані (`0x5cb26a7e7010`), далі йдуть глобальні неініціалізовані дані BSS (`0x5cb26a7e7018`).

- Розташування Купи (Heap): купа знаходиться над статичними сегментами даних. Динамічна пам'ять отримала адресу `0x5cb28195f2a0`, що є значно більшим значенням порівняно з BSS. Звідси купа має можливість зростати вгору (до більших адрес).
- Розташування Стека (Stack): стек знаходиться на самому верху доступного віртуального адресного простору процесу. Його адреси кардинально відрізняються (починаються з `0x7ffc...`) і знаходяться дуже далеко від купи та статичних даних. Початкова адреса стека дорівнювала `0x7ffc01d6c36c`. Після виклику функції `grow_stack()` та виділення пам'яті під великий локальний масив (40 КБ), адреса нової вершини стала `0x7ffc01d62700`. Оскільки нове значення менше за початкове (`0x7ffc01d62700 < 0x7ffc01d6c36c`), це експериментально підтверджує правило: на даній архітектурі стек зростає вниз, назустріч купі (у бік менших значень адрес пам'яті).
