## Завдання 3.1
Запустіть Docker-контейнер і поекспериментуйте з максимальним лімітом ресурсів відкритих файлів. Для цього виконайте команди у вказаному порядку:
```bash
$ ulimit -n                       (1)
$ ulimit -aS | grep "open files"  (2)
$ ulimit -aH | grep "open files"  (3)
$ ulimit -n 3000                  (4)
$ ulimit -aS | grep "open files"  (5)
$ ulimit -aH | grep "open files"  (6)
$ ulimit -n 3001                  (7)
$ ulimit -n 2000                  (8)
$ ulimit -n                       (9)
$ ulimit -aS | grep "open files"  (10)
$ ulimit -aH | grep "open files"  (11)
$ ulimit -n 3000                  (11)
```
Як наступне вправу, повторіть перераховані команди з root-правами.

## Теоретичні відомості та демонстрація 
Завдяки програмній документації до команди `ulimit` можна дізнатись, що комадна (1) вказує на максимальну кількість відкритих файлових дескрипторів. Приклад виводу:
```
andrew3378o@DESKTOP-N1R2BIO:~$ ulimit -n
10240
```

(2) — виводить поточне значення soft limit (м’якого ліміту) для відкритих файлів серед усіх інших ресурсів системи. М’який ліміт — це значення, яке система фактично використовує для обмеження процесу, але користувач може його змінювати самостійно в межах жорсткого ліміту. Приклад виводу:
```
andrew3378o@DESKTOP-N1R2BIO:~$ ulimit -aS | grep "open files"
open files                          (-n) 10240
```

(3) — виводить значення hard limit (жорсткого ліміту). Це «абсолютна стеля», встановлена адміністратором. Звичайний користувач не може підняти свій м’який ліміт вище цього значення. Приклад виводу:
```
andrew3378o@DESKTOP-N1R2BIO:~$ ulimit -aH | grep "open files"
open files                          (-n) 1048576
```

(4) — команда для зміни м’якого ліміту. Якщо число 3000 не перевищує поточний Hard limit, операція пройде успішно.

Приклад виводу після команди (5):
```
andrew3378o@DESKTOP-N1R2BIO:~$ ulimit -aS | grep "open files"
open files                          (-n) 3000
```

Приклад виводу після команди (6):
```
andrew3378o@DESKTOP-N1R2BIO:~$ ulimit -aH | grep "open files"
open files                          (-n) 3000
```

Приклад виводу після команди (7):
```
andrew3378o@DESKTOP-N1R2BIO:~$ ulimit -n 3001
-bash: ulimit: open files: cannot modify limit: Operation not permitted
```
Як можна помітити, після того як ми знизили hard limit до 3000 за допомогою команди (4), стає неможливим збільшити цей ліміт без прав доступу адміністратора. Схожими будуть всі інші операції після зниження ліміту до 2000.
