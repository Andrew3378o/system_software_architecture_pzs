
## Завдання 5.14
Побудувати сценарій, у якому malloc повертає успіх для великого розміру, але процес завершується пізніше через OOM при записі в сторінки.

### Технічна реалізація
Ядро Linux використовує оптимістичну стратегію виділення пам'яті (Memory Overcommit). Системний виклик `malloc()` виділяє лише віртуальний адресний простір, не резервуючи миттєво відповідні фізичні кадри. Завдяки цьому можна "успішно" виділити обсяг пам'яті, що значно перевищує наявну фізичну RAM. Фізична пам'ять виділяється лише під час фактичного доступу (читання або запису) за допомогою механізму відкладеного виділення — Demand Paging. 
Якщо процес починає інтенсивно записувати дані в ці сторінки, він вичерпує фізичні ресурси системи (RAM + Swap). Для запобігання повному зависанню операційної системи втручається механізм OOM Killer (Out-Of-Memory Killer), який примусово завершує процес сигналом `SIGKILL`. Щоб провести експеримент безпечно і не викликати зависання всієї ОС (явище thrashing), використовується механізм контрольних груп (cgroups) через утиліту `systemd-run`, яка ізолює процес і встановлює для нього жорсткі ліміти фізичної пам'яті.

### Тестування
**Запуск:**
Для безпечного тестування процес запускався з обмеженням фізичної оперативної пам'яті у 2 ГБ:
`gcc task5-14.c -o task5-14`
`systemd-run --user --scope -p MemoryMax=2G ./task5-14`
