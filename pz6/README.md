## Завдання 6.14
Замапити файл у пам’ять у режимах shared і private, змінити його вміст і проаналізувати поведінку dirty pages.

## Технічна реалізація 
Програма використовує системний виклик mmap() для відображення файлів у віртуальну пам'ять процесу та демонструє кардинальну різницю між двома режимами:

* MAP_PRIVATE (Механізм Copy-on-Write): При спробі змінити дані у пам'яті, ядро ОС створює ізольовану копію сторінки спеціально для нашого процесу. У системній статистиці такі сторінки позначаються як `Private_Dirty`. Оригінальний файл на диску захищений від змін і залишається в початковому стані, навіть якщо викликати `msync()`.

* MAP_SHARED (Прямий доступ до Page Cache): Зміни у пам'яті записуються безпосередньо у загальний кеш операційної системи. Такі модифіковані сторінки отримують статус `Shared_Dirty`. При виклику `msync()` (або з часом автоматично) ядро бере ці "брудні" сторінки та синхронізує їх з диском, фізично змінюючи оригінальний файл.

Для підтвердження теорії програма:

* Звертається до `/proc/self/smaps`, щоб зчитати реальну кількість брудних сторінок (в кілобайтах) за адресою нашого вказівника.

* Робить пряме читання файлу з диска (через `read()`), щоб перевірити, чи дійшли зміни з оперативної пам'яті до фізичного носія.

## Приклад використання
1. Компіляція програми: `gcc task6-14.c -o task6-14`
2. Запуск програми: `./task6-14`
3. Очікуваний результат:
```bash
simulation: MAP_PRIVATE (Copy-on-Write)
[before write] disk content:   'INITIAL_DATA'
[memory state] pointer value: 'PRIVATE_DATA'
    calling msync()...
[after msync ] disk content:   'INITIAL_DATA'

simulation: MAP_SHARED (Direct Cache)
[before write] disk content:   'INITIAL_DATA'
[memory state] pointer value: 'SHARED_DATA_'
    calling msync()...
[after msync ] disk content:   'SHARED_DATA_'
```
