
## Завдання 7.1
Використайте `popen()`, щоб передати вивід команди `rwho` до `more` у програмі на C.

### Технічна реалізація
Функція `popen()` запускає команду через `/bin/sh` і повертає `FILE*`, з'єднаний з її стандартним вводом або виводом через pipe. У програмі відкриваються два pipe-з'єднання: перше — з `rwho` у режимі читання (`"r"`), друге — з `more` у режимі запису (`"w"`). Дані передаються рядок за рядком через буфер за допомогою `fgets` та `fputs`. Оскільки `rwho` є мережевою утилітою і може бути відсутня в системі, команда складена з резервним варіантом через `||`: у разі невдачі `rwho` запускається `who`. Завершення роботи виконується через `pclose()`, який, на відміну від `fclose()`, додатково очікує завершення дочірнього процесу за допомогою `waitpid()`.

### Тестування та висновки
**Запуск:**
```
gcc -Wall task7-1.c -o task7-1
./task7-1
```

**Висновки:** Програма коректно з'єднує два процеси через pipe, відтворюючи поведінку конвеєра оболонки `rwho | more`. Якщо `rwho` недоступний, автоматично використовується резервна команда `who`. Вивід посторінково передається до `more`, де користувач може переміщатись між сторінками або вийти клавішею `q`.

## Завдання 7.2
Напишіть програму мовою C, яка імітує команду `ls -l` в UNIX — виводить список усіх файлів у поточному каталозі та перелічує права доступу тощо. Варіант вирішення, що просто виконує `ls -l` із вашої програми, не підходить.

### Технічна реалізація
Програма використовує три рівні API. Перший — `opendir` / `readdir` / `closedir` з `<dirent.h>` для обходу записів каталогу. Другий — системний виклик `lstat()` замість `stat()`, оскільки `lstat` не слідує за символічними посиланнями і повертає метадані самого посилання, що дозволяє коректно відображати тип `l`. Третій — `getpwuid()` та `getgrgid()` для перетворення числових UID і GID на текстові імена власника та групи через `/etc/passwd` і `/etc/group`. Права доступу формуються побітово з поля `st_mode` за допомогою макросів `S_IRUSR`, `S_IWUSR`, `S_IXUSR` та спеціальних бітів `S_ISUID`, `S_ISGID`, `S_ISVTX`. Час модифікації форматується через `strftime`: файли старші за 6 місяців відображаються з роком, новіші — з годиною та хвилиною.

### Тестування та висновки
**Запуск:**
```
gcc -Wall task7-2 -o task7-2
./task7-2
```

**Висновки:** Програма коректно відтворює формат виводу `ls -l`: тип і права доступу у десятисимвольному рядку, кількість жорстких посилань, ім'я власника та групи, розмір у байтах, час модифікації та ім'я файлу. Спеціальні біти `setuid`, `setgid` та `sticky` відображаються символами `s` і `t` відповідно до стандарту POSIX.

### Технічна реалізація
Програма приймає два аргументи командного рядка: шукане слово та ім'я файлу, перевіряючи коректність через `argc`. Символічні посилання на каталоги не спричиняють нескінченної рекурсії завдяки використанню `lstat`. Недоступні каталоги діагностуються без переривання роботи програми.

## Завдання 7.6

### Технічна реалізація
`readdir` повертає записи у порядку зберігання в inode файлової системи, який не є алфавітним. Тому програма реалізує дворівневий підхід: спочатку збирає всі імена підкаталогів у динамічний масив рядків через `strdup` (копіює у heap-пам'ять, оскільки буфер `entry->d_name` всередині `DIR` перезаписується при наступному виклику `readdir`), потім сортує масив через `qsort` зі стандартним `strcmp` як компаратором. Компаратор приймає `const void*` — вказівники на елементи масиву `char*[]` — і розіменовує їх до `const char*` перед передачею у `strcmp`. Після виведення кожен рядок звільняється через `free()` для запобігання витоку пам'яті.

### Тестування та висновки
**Запуск:**
```
gcc -Wall task7-6.c -o task7-6
./task7-6
```

**Висновки:** Програма коректно фільтрує лише підкаталоги, ігноруючи звичайні файли, та виводить їх у лексикографічному алфавітному порядку. Символічні посилання на каталоги не включаються завдяки `lstat`. За відсутності підкаталогів виводиться відповідне повідомлення.

## Завдання 7.9
Напишіть програму на C, яка вимірює час виконання фрагмента коду в мілісекундах.

### Технічна реалізація
Для вимірювання використовується `clock_gettime(CLOCK_MONOTONIC, &ts)` з `<time.h>`. Вибір `CLOCK_MONOTONIC` обґрунтований трьома перевагами над альтернативами: на відміну від `time()` він має наносекундну точність; на відміну від `clock()` він вимірює реальний (астрономічний) час, а не процесорний (CPU time), що важливо при наявності блокуючих операцій; на відміну від `CLOCK_REALTIME` він монотонний і не стрибає назад при синхронізації NTP. Структура `timespec` містить поля `tv_sec` (секунди) та `tv_nsec` (наносекунди), які перетворюються у мілісекунди за формулою `sec * 1000 + nsec / 1e6`. Змінна `result` оголошена як `volatile`, щоб заборонити компілятору оптимізувати та видалити цикл обчислень як непотрібний. Для компіляції необхідний прапорець `-lm` через використання `sqrt`.

### Тестування та висновки
**Запуск:**
```
gcc -Wall task7-9.c -o task7-9
./task7-9
```

**Висновки:** Програма коректно вимірює час виконання тестового циклу з обчисленням 10 мільйонів квадратних коренів. Результат виводиться з точністю до трьох знаків після коми у мілісекундах. Шаблон `t_start = now_ms(); код; t_end = now_ms();` є універсальним і може застосовуватись для вимірювання будь-якого довільного фрагмента коду.

## Завдання 7.10
Напишіть програму мовою C для створення послідовності випадкових чисел з плаваючою комою у діапазонах: (a) від 0.0 до 1.0; (b) від 0.0 до n, де n — будь-яке дійсне число з плаваючою точкою. Початкове значення генератора випадкових чисел має бути встановлене так, щоб гарантувати унікальну послідовність.

### Технічна реалізація
Генератор ініціалізується через `srand((unsigned int)time(NULL))`, де `time(NULL)` повертає кількість секунд з 1970-01-01, гарантуючи унікальну послідовність при кожному запуску (за умови що запуски рознесені в часі більш ніж на 1 секунду). Функція `rand_0_1()` обчислює значення у напіввідкритому інтервалі `[0.0, 1.0)` через ділення на `(double)RAND_MAX + 1.0` — саме `+ 1.0` запобігає досягненню рівно `1.0` та виконується у форматі `double` щоб уникнути цілочисельного переповнення при `RAND_MAX == INT_MAX`. Масштабування до `[0.0, n]` виконується простим множенням `rand_0_1() * n`. Верхня межа `n` зчитується через `scanf("%lf")` з перевіркою повернутого значення.

### Тестування та висновки
**Запуск:**
```
gcc -Wall task7-10.c -o task7-10
./task7-10
```

**Висновки:** Програма генерує 10 унікальних псевдовипадкових чисел у діапазоні `[0.0, 1.0)` та 10 чисел у діапазоні `[0.0, n]` для введеного користувачем значення `n`. Кожен запуск дає різну послідовність завдяки ініціалізації через поточний час. Числа рівномірно розподілені по всьому діапазону.

## Завдання 7.14
Реалізуйте засіб, який дозволяє відновити вилучений файл, якщо доступ до диску не було втрачено повністю.

### Технічна реалізація
Засіб базується на механізмі ядра Linux: системний виклик `unlink()` лише видаляє ім'я файлу з каталогу і зменшує лічильник посилань inode, але не стирає дані з диску поки хоча б один процес тримає файл відкритим. Ядро розкриває такі дескриптори через псевдофайлову систему `procfs`: шлях `/proc/<PID>/fd/<FD>` є символічним посиланням що вказує на оригінальний шлях з суфіксом ` (deleted)`. Програма сканує каталог `/proc` через `opendir`/`readdir`, фільтруючи числові записи (PID) через `strtol` з перевіркою `endptr`. Для кожного процесу читаються його дескриптори через `readlink`, і ті що містять ` (deleted)` зберігаються у масив структур `DeletedFile`. Оригінальний шлях відновлюється відсіканням суфіксу через `strstr` та обнуленням символу. Копіювання виконується блоками по 64 КБ з внутрішнім циклом що гарантує повний запис кожного блоку навіть при частковому `write()`. Підтримуються три режими запуску: перегляд, відновлення одного файлу та відновлення всіх знайдених файлів.

### Тестування та висновки
**Запуск:**
```
gcc -Wall task7-14.c -o task7-14
```

**Висновки:** Утиліта успішно виявляє вилучені файли що залишаються відкритими у процесах системи, відображає їх з інформацією про PID, номер дескриптора, розмір та оригінальний шлях. Відновлення через `/proc/<PID>/fd/<FD>` повністю відтворює вміст файлу. Якщо всі процеси закрили файл до запуску сканування — відновлення через `procfs` неможливе, оскільки ядро звільняє inode.
