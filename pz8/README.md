# Завдання 8.1
Чи може виклик `count = write(fd, buffer, nbytes);` повернути в змінній `count` значення, відмінне від `nbytes`? Якщо так, то чому? Наведіть робочий приклад програми, яка демонструє вашу відповідь.

## Теорія та реалізація
Системний виклик `write` може повертати значення менше за запитане число `nbytes` у випадках, коли виникає ситуація часткового запису через обмеження ресурсів або зовнішні переривання. Це часто трапляється при роботі з конвеєрами або сокетами, де об'єм внутрішнього буфера ядра обмежений, а також при виникненні сигналів під час виконання операції або через фізичне заповнення дискового простору. У наведеній програмі створюється анонімний канал, для якого встановлюється неблокуючий режим через `fcntl`, що дозволяє наочно побачити обмеження буфера при спробі записати 100 000 байтів, оскільки фактично записана кількість буде обмежена стандартним розміром системного буфера конвеєра.

# Завдання 8.2
Є файл, дескриптор якого — `fd`. Файл містить таку послідовність байтів: `4, 5, 2, 2, 3, 3, 7, 9, 1, 5`. У програмі виконується наступна послідовність системних викликів:
`lseek(fd, 3, SEEK_SET);`
`read(fd, &buffer, 4);`
де виклик `lseek` переміщує покажчик на третій байт файлу. Що буде містити буфер після завершення виклику `read`? Наведіть робочий приклад програми, яка демонструє вашу відповідь.

## Теорія та реалізація
Для файлу, що містить байтову послідовність 4, 5, 2, 2, 3, 3, 7, 9, 1, 5, виклик `lseek` переміщує внутрішній курсор файлу на зміщення 3, що відповідає четвертому елементу масиву. Наступний виклик `read` зчитує 4 байти поспіль, починаючи саме з цієї позиції, що охоплює байти за індексами 3, 4, 5 та 6. В результаті виконання цієї послідовності буфер буде містити значення 2, 3, 3 та 7, оскільки операція читання є послідовною та автоматично просуває вказівник файлу вперед на кількість прочитаних байтів.

# Завдання 8.4
Виконайте наступну програму на мові програмування С:

```c
int main() {
    int pid;
    pid = fork();
    printf("%d\n", pid);
}
```
Завершіть цю програму. Припускаючи, що виклик `fork()` був успішним, яким може бути результат виконання цієї програми?

## Теорія та реалізація
Системний виклик `fork` створює новий процес, який є майже ідентичною копією батьківського, за винятком значення, що повертається самим викликом. Батьківський процес отримує ідентифікатор (PID) створеної дитини, що є числом більше нуля, тоді як дочірній процес отримує нуль, що дозволяє програмі розрізняти контекст виконання. Обидва процеси після розгалуження продовжують виконувати наступну інструкцію `printf`, тому в терміналі з'являться два числа, порядок яких залежить від планувальника операційної системи, що демонструє асинхронну природу виконання процесів у UNIX-подібних системах.
